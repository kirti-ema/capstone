# WKND Adventures & Travel — Edge Delivery Services Capstone

> A pixel-accurate migration of the WKND demo site to **Adobe Experience Manager Edge Delivery Services (EDS)**, authored in **Document Authoring (DA / da.live)** and delivered as a fast, build-free, content-driven website.

---

## 1. Project Overview

**Purpose.** This project migrates the reference **WKND Adventures & Travel** site (source: `https://wknd.site/`) from a traditional AEM Sites implementation to **Adobe Edge Delivery Services**, an architecture that serves content directly from a document source with no build step and industry-leading Core Web Vitals.

**Problem it solves.** Traditional CMS front-ends are heavy, slow to author, and expensive to change. Edge Delivery Services decouples **content** (authored in Document Authoring) from **code** (blocks and styles in Git), so authors publish independently of developers, pages load near-instantly, and the same content model powers dynamic listings without a running application server.

**Target users.**

| Audience | What they do here |
|----------|-------------------|
| **Content authors** | Create and publish pages in DA (da.live) using pre-built blocks; no code required. |
| **Developers** | Build and style blocks in vanilla JS/CSS, maintain the query-index model and auto-blocking. |
| **Site administrators** | Manage Code Sync, preview/publish via the Admin API, and the DA Config Service. |
| **End users** | Visitors browsing the adventures, magazine, FAQs, and About Us content. |

**Business value.**

- **Performance:** targets a Lighthouse score of 100; no client-side framework, no bundler, automatic image optimization.
- **Authoring velocity:** authors publish through DA without developer involvement; dynamic listings update by editing a metadata field or a spreadsheet row.
- **Maintainability:** small, self-contained blocks; a single shared data-access utility; no transpilation to debug.
- **Low operating cost:** content is served from the edge; there is no application server or database to run.

## 2. Key Features

- **Pixel-accurate migration** of the WKND site design system (typography, color tokens, spacing) into `styles/brand.css`.
- **24 reusable blocks** covering heroes, carousels, cards, tabs, accordions, breadcrumbs, article layouts, and more.
- **Dynamic, index-driven listings** — magazine and adventure cards are generated from a query index, ordered by an authored `cardOrder` field.
- **Category-filtered Adventures tabs** (`tabs-filter`) with per-tab sorting rules.
- **Spreadsheet-driven components** — the FAQ accordion and About Us profile cards render from DA sheets (`faqs.json`, `contributors.json`); adding an entry is adding a row.
- **Block-per-section magazine articles** with a two-column editorial layout, share sidebar, and downloadable PDF assets.
- **Auto-blocking** — featured banners, author bios, and fragments are constructed from content patterns without explicit authoring.
- **Three-phase progressive loading** (eager → lazy → delayed) for optimal LCP.
- **Custom migration tooling** — Helix-importer scripts, parsers, and transformers used to bulk-import the source site.

---

## 3. Technology Stack

Edge Delivery Services is a serverless, document-backed architecture. It has no traditional application backend or relational database; the roles below are mapped to their EDS equivalents.

| Layer | Technology |
|-------|-----------|
| **Front-end** | Vanilla JavaScript (ES6+ modules, no transpiling), modern CSS3 (Grid, Flexbox, Custom Properties), semantic HTML5. **No framework, no build step.** |
| **Rendering backend** | Adobe Edge Delivery Services (`*.aem.page` / `*.aem.live`) — decorates author-produced markup and serves it from the edge. |
| **Content source (CMS)** | Document Authoring (DA / da.live) — the authoring surface and source of truth for page content. |
| **"Data layer"** | `query-index.json` feeds (generated by the platform from `helix-query.yaml`) and standalone DA **sheets** (`*.json`) — there is no relational database. |
| **Fonts** | Asar (headings) and Source Sans Pro (body), via Google Fonts. |
| **Tooling** | Node.js, `@adobe/aem-cli`, ESLint (Airbnb base), Stylelint (standard), Helix Importer (migration). |
| **CI/CD** | AEM Code Sync (GitHub App), GitHub Actions, `aem-psi-check` (PageSpeed gate). |
| **Hosting** | Adobe Edge Delivery Services CDN. |

## 4. Architecture Overview

### High-level flow

```
┌────────────────────┐        ┌─────────────────────┐        ┌──────────────────────┐
│  Document Authoring │  edit  │  Edge Delivery       │ serve  │  End users / browser │
│  (da.live)          │───────▶│  Services            │───────▶│  *.aem.page (preview)│
│  content + sheets   │ preview│  (decorates markup)  │        │  *.aem.live  (live)  │
└────────────────────┘        └─────────────────────┘        └──────────────────────┘
          ▲                              ▲
          │ Code Sync                    │ blocks / styles / scripts
          │                              │
   ┌──────┴───────────────────────────────────────┐
   │  GitHub repo (kirti-ema/capstone)             │
   │  blocks/  scripts/  styles/  helix-query.yaml │
   └───────────────────────────────────────────────┘
```

### Major components and interactions

- **Content (DA)** — pages authored as blocks and default content; the source of truth for everything users read.
- **Code (GitHub)** — `blocks/`, `scripts/`, and `styles/` are synced to EDS by the AEM Code Sync GitHub App on every push.
- **Page decoration (`scripts/scripts.js`)** — runs the three-phase load and `buildAutoBlocks()`, which constructs featured banners, magazine listings, author cards, and widgets from content patterns.
- **Shared data access (`scripts/query-index.js`)** — the single utility every dynamic block uses to fetch, cache, normalize, and sort a `query-index.json` feed.
- **Query indices (`helix-query.yaml`)** — define two feeds (`magazine`, `adventures`) with identical shapes, mapping authored metadata (`cardOrder`, `cardImage`, `category`, `publishDate`, `groupSize`, …) into indexed properties.
- **DA sheets** — standalone `.json` documents (`faqs.json`, `contributors.json`) that drive dual-mode blocks without touching a query index.

## 6. Installation and Setup

```sh
# 1. Clone the repository
git clone https://github.com/kirti-ema/capstone.git
cd capstone

# 2. Install dependencies
npm install

# 3. (Once, per environment) install the AEM CLI globally
npm install -g @adobe/aem-cli
```

**Content configuration.** There is no database to provision. Page content lives in Document Authoring and is served to the local dev server automatically once an author has previewed it. Code changes are picked up from your local working copy.

> **Note:** `content/**` is intentionally **git-ignored** — it lives in DA, not in the repository. Do not expect content files in a commit or PR.

## 7. Configuration

This is a build-free project with **no application environment variables or secrets in the repository**. Configuration is expressed through a small set of committed files:

| File | Purpose |
|------|---------|
| `helix-query.yaml` | Defines the query indices (`magazine`, `adventures`) and maps authored metadata to indexed properties. **The comments here are the source of truth for index field semantics.** |
| `head.html` | Global `<head>`: Content-Security-Policy, viewport, and the core script/style includes. |
| `.eslintrc.js` | ESLint config (Airbnb base; enforces `.js` import extensions and Unix line endings). |
| `.stylelintrc.json` | Stylelint standard configuration. |
| `.hlxignore` | Files excluded from being served by EDS (dotfiles, `*.md`, `LICENSE`, `package*.json`, `test/*`). |
| `.renovaterc.json` | Dependency-update automation. |
| DA Config Service | Binds the site to its DA content source and Block Library configuration (managed via the Admin/Config Service — not a committed file or secret). |

**Credentials.** Git, `admin.hlx.page`, and `admin.da.live` credentials are injected by the environment when the relevant opt-in is enabled — **never** hard-code or paste tokens.

## 8. Running the Application

Edge Delivery has **no build step** — code is served as authored.

```sh
# Start the local dev proxy (serves your local code + DA-previewed content)
aem up
# equivalent, without a global install:
npx -y @adobe/aem-cli up --no-open --forward-browser-logs
```

The dev server runs at **`http://localhost:3000`** with auto-reload.

```sh
# Lint before committing
npm run lint          # eslint + stylelint
npm run lint:fix      # auto-fix where possible

# Individual linters
npm run lint:js
npm run lint:css
```

Inspect delivered markup at any time:

```sh
curl http://localhost:3000/us/en/faqs            # decorated HTML
curl http://localhost:3000/us/en/faqs.plain.html # pre-decoration markup
curl http://localhost:3000/us/en/faqs.md         # markdown source
```

## 9. Usage Guide

### For content authors

1. Open the page in **da.live** and edit content using blocks and default content.
2. Use the **Block Library** panel to browse and insert available blocks.
3. **Preview** and then **Publish** from DA.
4. Dynamic content updates by editing metadata or sheets:
   - **Listing order / selection:** set the `Card Order` metadata field on a page.
   - **FAQ entries:** add a row to `faqs.json`.
   - **Contributors / guides:** add a row to `contributors.json`.

### For developers

1. Create or modify a block in `blocks/<name>/` (`<name>.js` + `<name>.css`).
2. Verify locally at `http://localhost:3000` and lint.
3. Push to a feature branch → open a PR to `main` (see [Contributing](#17-contributing-guidelines)).

### Typical end-user workflows

- Browse **Adventures** and filter by category tab.
- Read **Magazine** articles and download companion PDFs.
- Consult the **FAQs** accordion.
- Explore **About Us** contributor and guide profiles.

## 12. CI/CD and Deployment

### Pipeline

- **AEM Code Sync** (GitHub App) automatically processes pushes and makes code available on the matching preview environment.
- **GitHub Actions** (`.github/workflows/main.yaml`) run on push.
- **`aem-psi-check`** is a required check that **rejects a PR whose description lacks a preview/test URL** — every PR body must include a bulleted preview URL, e.g. `- https://main--capstone--kirti-ema.aem.page/`.

### Environments

| Environment | URL |
|-------------|-----|
| **Feature preview** | `https://{branch}--capstone--kirti-ema.aem.page/{path}` |
| **Production preview** | `https://main--capstone--kirti-ema.aem.page/{path}` |
| **Production live** | `https://main--capstone--kirti-ema.aem.live/{path}` |

### Deployment process

1. Push **code** to a feature branch → PR → merge to `main`; Code Sync publishes from `main` (allow ~30s).
2. Publish **content** separately via DA (preview → publish); content and code deploy independently.
3. A page is only served once it has been **previewed/published for that branch (ref)** — preview state is tracked per-ref.

## 13. Security Considerations

- **Authentication / authorization:** authoring and publishing are gated by **Adobe IMS** sign-in (DA) and GitHub permissions (code). The site itself is public, client-side-rendered content.
- **Secrets management:** **no secrets are committed.** Credentials for Git, `admin.hlx.page`, and `admin.da.live` are injected by the environment via an explicit opt-in — never pasted into chat, code, or config. A pasted token should be treated as compromised and rotated.
- **Content Security Policy:** enforced via `head.html` (`script-src 'nonce-aem' 'strict-dynamic'`, `object-src 'none'`, Trusted Types required for scripts).
- **Best practices:** everything shipped is public client-side code; dependencies are kept current via Renovate; `.hlxignore` prevents internal files from being served.

## 14. Known Limitations

- **CA locale (`/ca/en/`)** is a largely static parallel copy; it has not been migrated to the dynamic (index/sheet-driven) blocks. Matching CA query indices would be needed to bring it into scope.
- **Query-index freshness lag** — after authoring `publishDate`/`category`/`groupSize`, `query-index.json` can remain stale for minutes; features must not assume the index is instantly fresh.
- **Static SHARE sidebar by design** — the article "Share This Story" list is intentionally static because of the index lag above.
- **Local `.plain.html` files are render snapshots, not re-postable sources** for image markup — a naive "sync" (local → DA) can break images on pages that use the compact `/media-da/` image form. Refresh local **from** DA before syncing.
- **Root `/` serves the default AEM boilerplate** placeholder; the real homepage is `/us/en`.

### Future enhancements

- Migrate the CA locale to dynamic blocks with matching indices.
- Re-introduce a dynamic SHARE sidebar once `publishDate` indexing is reliably fresh.
- Optional branded landing/redirect at the site root.

## 15. Troubleshooting

| Symptom | Likely cause | Resolution |
|---------|--------------|------------|
| Image renders as `about:error` | Absolute `content.da.live` URL in a `<source>` (returns 401 to the optimizer) | Use the DA Media Library "Copy" URL (`…aem.live/media_<hash>.ext`) or the relative `/media-da/` form; verify on the rendered preview. |
| Download / sheet link 404s (`-pdf`, `-json`) | DA normalizes a `.ext` in a link href to `-ext` | Ensure the href resolves; correct to the dot form in **both** local and DA. Grep with an **escaped dot** to detect it. |
| A DA edit "reverted" after a sync | Sync overwrites DA **from local**; the local file was stale | Always edit **both** local and DA, then verify parity; refresh local from DA before syncing. |
| Page returns 404 while code looks fine | Content not previewed/published for that ref | Preview/publish the page for the correct branch; confirm via the Admin status API. |
| PR rejected by `aem-psi-check` | PR description lacks a preview URL | Add a bulleted `- https://main--capstone--kirti-ema.aem.page/` to the PR body and re-run. |
| Image fix visible locally but not live | `/media-da/` paths resolve only inside EDS render | Verify on the deployed **preview**, not `curl` or the local dev server. |

## 16. Contributing Guidelines

### Branching strategy

- `main` — the deploy branch; Code Sync publishes from here.
- `develop` — active integration branch.
- Feature branches → PR into `main` (or `develop`, then `main`).

### Pull request process

1. Push your feature branch; wait ~30s for Code Sync to build the preview.
2. Run `npm run lint` and confirm it passes.
3. Open a PR **including a preview URL** in the description — `https://{branch}--capstone--kirti-ema.aem.page/{path}` — or the `aem-psi-check` gate will reject it.
4. Verify `gh pr checks` (Code Sync, linting, PSI).
5. A reviewer inspects the code and preview, then merges. Code Sync updates production from `main`.

### Coding standards

- **JavaScript:** ES6+; Airbnb ESLint rules; always include `.js` import extensions; Unix (LF) line endings.
- **CSS:** Stylelint standard; mobile-first with `min-width` breakpoints at **600 / 900 / 1200px**; **scope all block CSS to `.{blockname}`** (avoid bare selectors and `{blockname}-container`/`-wrapper`).
- **Blocks:** self-contained (`<name>.js` + `<name>.css`); export a default `decorate(block)`; responsive and accessible by default.
- **Never modify `scripts/aem.js`.**
- See **`AGENTS.md`** for the full engineering guidelines.
